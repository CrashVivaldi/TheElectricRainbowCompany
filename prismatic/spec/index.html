1. Overview

A .prsm file is a holographic image container. It encodes a photograph or layered composition together with a depth map and rendering parameters sufficient to reproduce a tilt-reactive, iridescent holographic card effect in any conforming viewer.

The file is a valid HTML document with a non-standard extension. Any web browser can open it without a plugin or OS-level file association. The renderer may be inlined in the file (self-contained mode) or loaded from a CDN via a <script> tag (linked mode). The image data and all rendering parameters are encoded in a manifest JSON block embedded in the document <head>.

The format has two content types: photo (a single image with an associated depth map) and diorama (up to four transparent-PNG layers composited at independent depth values). Both types are rendered by the same engine using the same manifest schema.

2. File structure

A conforming .prsm file must be a valid HTML5 document containing exactly:

  1. A <script type="application/json" id="prsm-manifest"> element in the <head> whose text content is the manifest JSON (see §3).
  2. A <prismatic-card> custom element in the <body>.
  3. A <script> element that defines the prismatic-card custom element — either inline (self-contained mode) or as a src reference (linked mode).

2.1 Self-contained mode

The engine script is inlined verbatim. The file opens and renders with no network access. This is the default output of the Prismatic authoring tool.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <script type="application/json" id="prsm-manifest">
    { ...manifest JSON... }
  </script>
</head>
<body>
  <prismatic-card></prismatic-card>
  <script>/* prismatic.js inlined */</script>
</body>
</html>

2.2 Linked mode

The engine is loaded from a URL. Linked-mode files are not self-contained and may fail to render offline.

<prismatic-card></prismatic-card>
<script src="https://theelectricrainbowcompany.com/prismatic.js"></script>

2.3 Prohibited patterns

A .prsm file MUST NOT contain a literal </script> inside any <script> element's text content. The sequence must be escaped as \u003c/script>.

3. Manifest schema

The manifest is a UTF-8 JSON object. Unknown keys MUST be ignored by conforming readers. All fields are optional except version and type.

{
  "$schema": "https://theelectricrainbowcompany.com/schema/prsm/v1.json",
  "version": 1,               // integer, required
  "type": "photo",            // string, required — "photo" | "diorama"
  "title": "Untitled",

  "photo": {
    "src": null,              // string | null — base64 JPEG data URL
    "depth": null,            // string | null — base64 JPEG data URL
    "depthMode": "custom"     // "custom" | "heuristic" | "auto"
  },

  "diorama": {
    "layers": [               // 0–4 objects, back-to-front
      {
        "src": null,          // string | null — base64 PNG data URL
        "depth": 0.0,         // [-1.0, 1.0]  negative=near, positive=far
        "opacity": 1.0        // [0.0, 1.0]
      }
    ],
    "strength": 70            // [0, 100]
  },

  "foil": {
    "style": "spectrum",      // "spectrum" | "mono"
    "hue": 140,               // [0, 360]  base hue in degrees (mono only)
    "grain": 0.45,            // [0.0, 1.0]  per-facet grain (mono only)
    "opacity": 0.45,          // [0.0, 1.0]
    "sparkle": 0.7,           // [0.0, 2.0]
    "size": 16,               // [10, 28]  logical pixels
    "facetType": "diamond"    // "diamond" | "hex" | "prism" | "flecks"
  },

  "effects": {
    "strength": 0.18,         // [0.0, 1.0]  parallax displacement
    "focus": 0.5,             // [0.0, 1.0]  depth focal plane
    "edge": 0.18,             // [0.0, 1.0]  edge-fill softness
    "blur": 0.0,              // [0.0, 1.0]  depth-of-field
    "brightness": 1.0,        // [0.4, 1.8]
    "saturation": 1.0,        // [0.0, 2.0]
    "tintHue": 190,           // [0, 360]
    "tintAmount": 0.0,        // [0.0, 1.0]
    "chromAb": 0.0,           // [0.0, 1.0]  chromatic aberration
    "vignette": 0.3,          // [0.0, 1.0]
    "grain": 0.04,            // [0.0, 1.0]  animated film grain
    "photoOpacity": 1.0,      // [0.0, 1.0]
    "invertDepth": false,
    "wrapTilt": false,        // sine-wrap tilt input
    "stretchToFit": true,     // true=stretch, false=crop-to-fill
    "photoFoil": true,
    "borderFoil": true,
    "borderSparkle": 0.6,     // [0.0, 2.0]
    "borderSize": 16          // [10, 28]
  },

  "tilt": {
    "rotAmt": 10,             // [0, 30]  CSS 3D rotation in degrees
    "gyroSens": 1.0,          // [0.5, 2.0]
    "invertX": false,
    "invertY": false
  }
}

3.1 Type semantics

When type is "photo", a conforming reader MUST use photo.src as the primary image and photo.depth as the depth map. If photo.depth is null, the reader generates depth according to photo.depthMode.

When type is "diorama", a conforming reader MUST composite diorama.layers back-to-front into a single image and depth map before rendering, using each layer's alpha channel for occlusion. If no layers have image data, the reader MAY fall back to photo.src.

Both sections MUST be present in the manifest regardless of type, allowing a viewer to switch modes on a received file.

3.2 Image data encoding

All image data MUST be encoded as RFC 2397 data URLs. Photo and depth MUST be JPEG. Diorama layers MUST be PNG (alpha channel required). Readers SHOULD accept either format for forward compatibility.

3.3 Depth map conventions

Grayscale image, R channel used. White (1.0) = near; black (0.0) = far. May be inverted via effects.invertDepth. If depth dimensions differ from the photo, readers MUST scale using cover-fit geometry.

3.4 Version negotiation

Readers encountering version > 1 SHOULD warn and render using known fields. Readers encountering version < 1 or a missing version MUST treat the file as version 1.

4. Renderer requirements

A conforming renderer MUST:

  • Read the manifest from #prsm-manifest in the host document.
  • Ignore unknown manifest keys without erroring.
  • Support both "photo" and "diorama" content types.
  • Support gyroscope input via DeviceOrientationEvent, behind a user permission prompt where required (currently iOS).
  • Request gyroscope permission only after explicit user interaction.
  • Honor prefers-reduced-motion by disabling tilt animation when set.

A conforming renderer SHOULD:

  • Support mouse/pointer tilt on non-touch devices.
  • Lerp tilt toward target for smooth movement (reference: 0.14 factor per frame at 60 fps).
  • Render the border foil frame when effects.borderFoil is true.
  • Support all four foil.facetType values.

A conforming renderer MAY:

  • Omit depth-of-field blur if the environment does not support it.
  • Fall back to a flat render if WebGL is unavailable.

5. Security considerations

.prsm files are HTML documents subject to standard browser security policies. Authoring tools SHOULD cap source images at 1280px (photos) and 1024px (diorama layers) before encoding. Authoring tools MUST escape </script> within manifest JSON as \u003c/script>. Self-contained files have no external dependencies and are safe to share as attachments.
